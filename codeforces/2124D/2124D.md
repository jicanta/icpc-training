## Make a Palindrome
First, it's clear that we cannot delete any of the smallest $k-1$ elements (even if we considered the whole array, there would not be enough "small" values to make it be the kth smallest).
Now, as long as the $k-1$ smallest elements remain in the array, we can delete any other element in any way we want.
To make the array a palindrome, we want first and last elements to be equal, second and second-to-last, and so on.
We can get rid of every element that's not in the "$k-1$ smallest elements set".
Now, we must strategically delete elements to make a palindrome array. It's important to notice that we must remove as little elements as possible. Hence, a greedy two pointer algorithm will work:
Try to match first and last elements. If it's not possible, you must delete one of them.
The subtlety is the following:
Let x be the $(k-1)$th smallest element in the array (always consdering by number of occurences, like a multiset).
You can't eliminate any occurence of elements smaller than x, but you may delete some occurences of x.
We can move with 2 pointers, only deleting x values when they dont coincide. If in the end we have less than $k-1$ elements, then there is no solution. This makes sense, because no operation is valid on intervals of length less than k, and if we have exactly k elements, apllying the operationce once results in k-1 elements and we cannot further apply the operation.
